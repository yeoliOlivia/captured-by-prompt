# Existing-system audit — October 12, 2026

The existing search and context application passes the automated checks listed below after the fixes in this change. This is not a certification of production readiness or model accuracy. Live provider calls and physical-device execution were not performed.

## Scope

Reviewed browser search, Gemini/Qwen adapters, embedding math and provider isolation, strictness filtering, context resolution/storage, uploads/folder imports, restart recovery, portable dataset bundles, workspace authentication, mobile API/storage/context integration, dependencies, and build configuration. The archived API/core code was inspected and its regression suite run; active clients still use the shared playground backend.

Excluded the newest native iPhone Photos improvements as requested: no review or device validation of native sharing, favorites, albums, deletion, or the selection/action flow. The existing unit tests for those features still ran as part of the unchanged overall suite. No user's photo library was modified and no live dataset was reindexed.

## Findings fixed

| Finding | Previous behavior | Change and evidence |
| --- | --- | --- |
| Browser upload recovery | A failed initial state fetch left `uploading` true, blocking subsequent uploads. | Cleanup now covers that fetch. A browser test interrupts it, reconnects, and successfully uploads. |
| Stale rankings across clients | Another tab could switch provider or edit context while the browser retained old matches. Mobile refresh detected model changes but not context changes. | State includes an opaque context version. Clients invalidate results when relevant workspace state changes. Browser tests cover both external changes and delayed local context saves during polling. Mobile invalidation is checked by code review/typechecking; its UI was not device-tested. |
| Mobile clarification memory | Naming “my brother” as “Alex” saved Alex without necessarily remembering “my brother.” | The original phrase is retained as an alias; “me” is stored explicitly. Clarification bindings survive refresh before the next question. Added draft tests. |
| Damaged server cache | One malformed record, missing image, or invalid known-provider vector could prevent the entire server from starting. | Bad records are reported and left on disk. Valid photos remain available; invalid vectors are marked for reanalysis. A regression test proves recovery without repeating already-completed analysis. Damaged personal-context SQLite databases still require restoration from backup. |
| Damaged legacy mobile analysis | Invalid JSON in an obsolete analysis field prevented loading otherwise usable photos and workspace links. | Treat this optional legacy cache as unavailable, preserving the collection and mappings. Tested with real SQLite. |
| Mobile search timeout | The client timed out after 180 seconds, although a personal search can make four sequential provider calls with 90-second limits. | Search allows 390 seconds; other calls retain 180 seconds. A simulated slow personal search verifies the longer allowance and timer cleanup. |
| Vector normalization | Extreme finite components could overflow the norm and silently produce an all-zero vector. | Scale before normalizing. Zero and nonfinite input still fail. Added regression coverage. |
| Alias whitespace | Leading whitespace prevented article normalization, so “ The Japan trip” differed from “Japan trip.” | Trim before normalizing articles; regression test added. |
| Bundle validation | Correct checksums could pass despite mismatched image/record pairs or unusable embeddings. | Validate pairing, content-based image IDs, model, dimensions, record fields, finite nonzero vectors, and collection count. Tests include maliciously recomputed checksums. |
| Vulnerable dependencies | Installed `sharp`, `shell-quote`, and `source-map-js` versions had published advisories. | Compatible lockfile updates: sharp 0.35.5 (updated libvips artifacts), shell-quote 1.12.0, source-map-js 1.2.2. No Expo SDK downgrade or forced major migration. |

The Gemini adapter test uses the real installed Google SDK with intercepted HTTP responses; it checks image bytes, requested dimensions, and the context/verification requests. Qwen tests check raw-image/text request construction and separate provider caches. Neither proves credentials, quotas, region eligibility, or live model outputs.

For browser checks on a fresh clone, run `npm ci`, then `npx playwright install chromium`, then `npm run test:browser`. The test uses an ephemeral localhost port and temporary synthetic images. It does not connect to the user's running server or use provider credentials.

## Remaining issues and limits

1. **Dependency advisories remain.** After compatible patches, the production dependency scan reports 29 affected package entries: 19 high and 10 moderate, zero critical. These trace to four underlying advisories, rather than 29 independent flaws. `braces` and `node-forge` affect build/tooling dependencies; `uuid` is pulled through Xcode tooling; `decode-uri-component` is used through query-string/Expo Router and needs runtime consideration. Exposure has not been conclusively ruled out. The scan suggests incompatible Expo/React Native downgrades for some chains; those were deliberately not applied. Resolve via supported upstream patches or a separately validated SDK migration before a production release.
2. **No live Gemini/Qwen acceptance test.** Request formats were compared with current primary documentation, but this audit used no real API credentials. A small consented live test remains necessary for both providers. Hosted Qwen is the Beijing `qwen3-vl-embedding` service, not a self-hosted Qwen3-VL-Embedding-8B checkpoint or Modal deployment.
3. **Retrieval quality is not established by software tests.** Cosine similarity is not a calibrated probability. Visual verification checks at most 12 retrieved candidates; matches missed by retrieval cannot be recovered by that check. Personal retrieval combines query/reference similarity and explicit photo associations; there is no dedicated face-identity system. Dates in saved context do not create reliable capture-date filtering when candidate metadata is absent. Evaluate these separately with labeled queries and relevant/nonrelevant photos.
4. **Still a local, single-owner prototype.** The bearer token protects access to one workspace; it is not multi-user authorization. Model keys stay in process memory. LAN development uses HTTP on trusted Wi-Fi. Internet deployment requires HTTPS and account/data isolation. No full-library synchronization or post-training/LoRA system exists.
5. **iPhone runtime remains unverified.** Mobile TypeScript, API/storage tests, and JS export pass. Native signing, picker/permission behavior, filesystem bridges, and real-device networking still need a device test. The newest Photos actions were outside this audit.
